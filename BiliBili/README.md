# 📺 哔哩哔哩去广告 + CDN 自定义

Surge 模块，去除哔哩哔哩 App 的广告，并可把视频分片重定向到指定 CDN。

```
https://raw.githubusercontent.com/SkyBlue997/Surge/main/BiliBili/BiliBili.ADBlock.sgmodule
```

## 文件

| 文件 | 作用 |
|---|---|
| `BiliBili.ADBlock.sgmodule` | 模块本体，所有开关都在模块参数里 |
| `BiliBili.ADBlock.js` | 响应脚本：JSON 与 gRPC 去广告 |
| `BiliBili.CDN.js` | 请求脚本：视频 CDN 重定向 |

gRPC 接口不依赖任何 protobuf 库：脚本自带 gzip 解压和 protobuf 线格式解析，只改动广告相关字段，其余字段保留原始字节。即使 App 更新后 proto 有新增字段，也不会被破坏。

## CDN 自定义

App 播放视频时会用 HTTPDNS 直接连 IP（URL 是 `https://185.x.x.x/upgcxcode/...`，真实主机在 `Host` 头里），按域名匹配的规则抓不到这种请求。本脚本以 `Host` 头为准识别来源，然后只替换主机，路径和 `upsig` 签名原样保留。

- `CDN.UPOS`：官方 CDN 的目标主机。默认 `AUTO` 自动测速；`OFF` 为不改写；也可填固定主机。
- `CDN.PCDN`：PCDN / MCDN（家庭宽带 P2P）的处理方式，默认 `UPOS`，即改回官方 CDN（`AUTO` 时用测速结果）。

### 自动测速 (`CDN.UPOS=AUTO`)

测速用的是最近一次播放时的**真实签名链接**，所以测出的是实际视频的下载速度，也顺带验证了该节点能不能播这类视频。结果按网络分别保存（每个 Wi-Fi 名称、蜂窝运营商各一份）。

| 时机 | 做什么 | 会不会拖慢播放 |
|---|---|---|
| 当前网络没有任何结果 | 播放第一个分片时，所有候选同时下载 `CDN.TestSize`，最先完成的胜出 | 只拖慢这一个分片，最多 3 秒 |
| 网络切换 | 等 3 秒后在后台逐个完整测速 | 否 |
| 每 30 分钟 | 结果过期 (`CDN.TTL`) 且近 2 小时看过视频时，后台完整测速；没看视频就什么都不做 | 否 |
| 首页面板「B站 CDN」 | 显示排名；点按刷新立即完整测速 | 否 |
| 选中的节点返回 4xx / 5xx | 302 回原地址，标记该节点失败，下次测速时排除 | 只影响这一个分片 |

- **完整测速**：逐个节点测，避免互相抢带宽。每个节点先发一个 16KB 请求预热连接并记录延迟，再下载 `CDN.TestSize` 测速度，最后按速度排序。默认 10 个候选，每次约消耗 5MB 流量、耗时十几秒。
- **原主机也参与比较**：视频原本使用的主机也是候选；如果它最快就不改写，保留 App 的 HTTPDNS 直连。
- **候选列表可改**：通过 `CDN.Candidates` 调整，用 `|` 分隔。Akamai 会被自动排除。

一次真实的完整测速（Mac 所在网络，2026-10-25，512KB）：

```
1. upos-sz-mirroraliov  13.9 MB/s · 48ms
2. upos-sz-mirrorcosov  10.2 MB/s · 91ms
3. cn-hk-eq-01-12        1.2 MB/s · 319ms
…
9. upos-sz-mirrorcos     0.18 MB/s · 2243ms
```

同一天早些时候用 curl 手测（1KB 首包时间）时，`cn-hk-eq-01-12` 比 `aliov` 快。节点表现会随时间变化，这也是自动测速的意义。

### 手动选择参考

实测（日本网络，2026-10-25）同一分片换主机的结果：

| 目标主机 | cosov 来源 | Akamai 来源 |
|---|---|---|
| upos-sz-mirrorcosov | ✅ 54ms | ✅ 720ms |
| upos-sz-mirroraliov | ✅ 448ms | ✅ 306ms |
| cn-hk-eq-01-12 | ✅ 267ms | ✅ 229ms |
| upos-sz-mirrorcos | ✅ 4.4s | ✅ 1.8s |
| upos-sz-mirrorali | ❌ 超时 | — |
| upos-hz-mirrorakam (Akamai) | ❌ 403 | — |

所以 Akamai 只能作来源，不能作目标；海外网络建议选 `cn-hk-eq-01-*` 或 `*ov` 主机。

> 视频 CDN 的 MITM 会额外解密视频流量。不需要换 CDN 时，可以在 `[MITM]` 里删掉 `upos-*` 及之后的主机名。

## 使用前确认

1. Surge 首页的 **MitM**、**重写**、**脚本** 三个开关都已打开。
2. MitM 证书已安装，并在「设置 → 通用 → 关于本机 → 证书信任设置」中完全信任。
3. 生效后，在「最近请求」里打开 `app.bilibili.com/x/v2/splash/list`，备注里应能看到 `[Script]` 开头的日志。看不到说明脚本没有执行，问题不在规则本身。

## 未覆盖

- 旧版播放页接口 `bilibili.app.view.v1.View`（新版 App 已改用 `viewunite`），抓包中没有样本。
- 推荐流去除广告后不补位，单列 / 双列布局里可能少一张卡片。
- 自动测速只比较官方 CDN 主机，不比较 App 通过 HTTPDNS 拿到的具体 IP；原主机是按域名解析后测的。
- 测速样本（最近一个视频分片链接，含账号 mid / buvid 参数）只保存在本机 Surge 的持久化存储里，不会上传。
